# 项目结构讨论

状态：用户已确认 V0 方案。按模块逐步实现；已经完成 uv、最小 FastAPI 服务、单 PDF 逐页解析、语料清单与批量解析、保留页码的文本切块、可切换的本机 Embedding 接口、Milvus/Attu 的 Docker 环境、批量索引入口和 Dense Retrieval 检索适配。下一模块处理百炼回答和引用校验。以下结构描述完整 V0 目标，不表示所有模块已实现。

## 已明确

- 项目面向个人使用。
- 第一版网页支持提问、返回回答及参考来源。
- 参考来源必须来自本次真实检索且实际交给回答模型的内容。
- 引用展示文件名、页码和实际提供给模型的片段；后端提供来源元数据，并校验回答中的引用编号。
- 第一版每次提问独立处理，不将历史问答作为下一次请求的上下文。
- 当前只实现独立的一问一答，会话存储留待后续；后续将逐步补充短期记忆和长期记忆，具体语义与实现届时讨论。
- 证据不足时明确说明不足及缺失内容；可回答有证据支持的部分，不用模型自身知识补出无文档依据的结论。
- V1 是 V0 的后续改进版本，不要求多个版本同时在线回答问题。
- 使用 uv 管理 Python 环境，后端采用 FastAPI 和 LangChain 生态。向量数据库确定为 Milvus，通过 Docker 运行；关系数据库在会话存储阶段再引入，具体产品届时确定。
- V0 使用 PyMuPDF 逐页提取文本，不做标题、段落类型和表格结构识别。Unstructured 与 MinerU 留到后续解析优化和对比阶段。
- 前端由 AI 根据用户需求实现，使用 React、TypeScript 和 Vite。第一版提供有成品感的完整问答体验；前端技术不是本项目的主要学习目标。
- 回答模型先按阿里云百炼接入方向规划，具体模型尚未确定；未来可替换回答模型。
- Embedding 使用本机运行的模型，当前默认 Qwen/Qwen3-Embedding-0.6B，并保留 BAAI/bge-m3 作为对照；模型、设备、批大小和归一化参数从 `.env` 读取，不为此启用台式机。
- 先共同确认结构，再逐个模块实现和讲解。
- 既有项目路线包含使用同一套评测数据比较版本效果与代价。

## 已确认的实现约定

- 前后端放在同一个仓库，Python 使用一个 src 布局的包；前端使用 React、TypeScript 和 Vite，由 AI 实现。
- V0 使用 LangChain 的文档、切块、Embedding、检索和模型调用组件，直接组织检索后生成的流程；暂不引入 LangGraph 或 Deep Agents。
- 文档准备与网页问答分开。解析、切块、建库和评测提供命令入口，第一版网页只提供独立提问和结果、来源展示。
- 第一版采用完整响应：等待本次生成与引用校验结束后，一起返回答案和来源。流式响应留待后续需要时增加。
- 第一版前端包含统一布局与视觉风格、输入与提交、加载状态、错误提示与重试、Markdown 回答、引用与来源卡片，以及打开对应 PDF 的入口。证据不足时明确提示；页面说明每次提问独立处理。页面组件与接口调用分开组织，供后续会话管理、文档管理等功能复用。
- 初始开发在本机通过 uv 运行 Python；通过 Docker Compose 运行 Milvus Standalone 及配套依赖，数据库数据持久化。
- 批量评测产物保存为文件，不增加 V0 会话数据库。通过代码版本、依赖锁文件、文档哈希、解析产物、索引清单、运行配置和逐题结果保留历史基线。
- Embedding 模型名、模型版本、设备、归一化设置和向量维度属于索引配置的一部分；切换 Embedding 模型后建立新的 Milvus collection，不能把不同模型生成的向量混写到同一个 collection。
- 解析后没有可用文本的页记录异常；由于引用需要来源页码，缺少页码的内容不能静默入库。遇到无效引用编号，返回可理解的失败状态，不将未通过校验的回答当成成功结果。

## 模块实现时再确定的参数

沿用用户已初始化的 Python 3.13 与 Python 包名 agenticrag。具体依赖版本、Milvus 镜像版本、百炼模型标识、BGE 型号与权重版本、切块大小和重叠、Top-K、向量相似度度量与索引参数，在相应模块实施时配置并记录；这些参数不要求另建应用或改变本文的职责划分。API 凭据保存在本机环境变量或未提交的 .env 中，源码仅提供 .env.example，前端不持有模型凭据。

后续阶段再设计会话存储、短期与长期记忆、关系数据库、Unstructured/MinerU 的具体接入，以及需要分支或自主决策时的 LangGraph/Deep Agents 用法。

## 目标目录

采用同一仓库组织前端、一个 Python 后端包、数据与评测。目录按实现阶段逐步增加：

```text
AgenticRag/
├── pyproject.toml
├── uv.lock
├── compose.yaml
├── .env.example
├── .gitignore
├── README.md
├── src/agenticrag/
│   ├── api/          # 网页接口与请求、响应结构
│   ├── ingestion/    # 解析结果加载、切块及索引构建
│   ├── rag/          # 在线检索、生成及引用校验
│   ├── integrations/ # 百炼模型、本机 BGE、Milvus 的接入
│   └── config.py
├── frontend/
├── corpus/           # 现有 PDF 保持此位置
├── qa.jsonl          # 现有问答样本保持此位置
├── artifacts/        # 解析结果、索引清单、评测运行产物
├── evaluation/       # 批量评测入口及评分逻辑
├── tests/
├── docs/
└── CONTEXT.md
```

小模块按实现需要增加文件，不预先为每个函数建立抽象层。模型权重放配置指定的本机缓存或模型目录，不纳入源码版本管理。

Milvus 选型已确定，参见 [ADR 0001](adr/0001-milvus-vector-store.md)。建议先采用 Standalone 及对应的 Docker Compose 部署，具体版本在环境准备时确认并固定。关系数据库确定推迟到会话存储阶段引入。

## 数据准备、问答与评测的边界

数据准备：corpus 中的 PDF → PyMuPDF 逐页文本 → 按页切块 → 本机 BGE → Milvus。每个片段保留文档标识、PDF 物理页码（从 1 开始）、片段标识及来源文件；文档文件名由现有映射取得。不识别版面结构，不代表丢弃页码等来源信息。

在线问答：网页 → FastAPI → 问题向量化 → Milvus 检索 → 构建实际生成上下文 → 百炼回答模型 → 引用身份校验 → 返回答案与来源。问题向量化与文档向量化必须使用一致的 Embedding 模型和编码配置。模型在本机进程中复用，不为每次请求重新加载权重。

代码依赖：api 调用 rag 的问答入口；evaluation 也调用同一个问答入口，不需要启动网页。ingestion 和 rag 复用 integrations 中的 Embedding 与 Milvus 接入。rag 不依赖网页请求对象，也不读取 qa.jsonl 的答案。

评测：读取 qa.jsonl 的 question 调用问答入口，以 gold 及必要的人工核对评价输出，保存逐题结果和本次配置。V0 标准输入为问题和检索内容；gold、reasoning、sub_answers、decomposed_queries 和 external_knowledge 等评测样本附加字段不自动进入生成上下文。如果后续增加公式辅助，作为独立实验设置记录。文档级命中可以通过既有映射检查；证据片段 Recall@K 需要先补充相应证据标注，不能用命中文档代替命中具体证据。

tests 检查程序行为是否符合约定；evaluation 检查真实问答效果。两者分开命名，避免将单元测试通过误认为 RAG 答案质量达标。

## 后续解析器比较

解析实现放在 ingestion 的解析模块中；PDF 到解析内容的转换和后续切块分开。将来添加 Unstructured 或 MinerU 时，统一适配需要保留其可提供的结构信息，以支持有意义的比较。Unstructured 的 fast 与 hi_res 作为不同实验配置记录。

输出按解析器和运行标识分开存放，例如 artifacts/parsed/pymupdf/<run_id>/ 与 artifacts/parsed/mineru/<run_id>/，避免覆盖。每次记录原始 PDF 哈希、解析器版本与配置、文档标识、PDF 物理页码（从 1 开始）及解析内容。无法提取的页应记录异常，不能悄悄丢弃或虚构页码。

比较解析器时，为每组解析产物建立独立的 Milvus collection，并固定文档、题目、切块策略、Embedding 模型、检索参数、回答模型与提示词。相同切块策略不保证不同解析输出产生相同片段，应保存各次实际片段和配置。观察指标包括文本与表格证据保留、检索和回答效果、处理耗时。

## 来源需求的例子

若检索得到 A、B、C 三个片段，而最终只把 A、B 交给回答模型，C 不能列为本次回答的引用来源。合法来源身份只说明它进入过生成上下文，不能单独证明回答中的结论受到该来源支持。
